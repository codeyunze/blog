# Kafka 3.9.2 单机版（KRaft 模式）与 Kafka-UI 部署记录

## 1. 环境准备

在部署 Kafka 之前，需预先创建数据与日志目录，并配置正确的文件权限，以防止容器启动时因权限不足导致写入失败。

```bash
# 创建数据和日志目录
mkdir -p kafka-single/{data,logs}
cd kafka-single

# 设置目录权限（Kafka 容器默认使用 UID 1000 的 appuser 运行）
sudo chown -R 1000:1000 ./data ./logs
sudo chmod -R 755 ./data ./logs
```

## 2. Kafka 部署配置

### 2.1 docker-compose.yml 核心配置

以下为 Kafka 3.9.2 单机版（KRaft 模式）的完整 Docker Compose 配置：

```yaml
version: '3.8'
services:
  kafka:
    image: apache/kafka:3.9.2
    container_name: kafka-single
    restart: always
    ports:
      - "9092:9092"
      - "9093:9093"
    environment:
      # 节点与角色配置
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller

      # 监听器配置
      KAFKA_LISTENERS: PLAINTEXT://9092,CONTROLLER://9093
      # ⚠️ 关键配置：Docker 容器间通信必须使用服务名 'kafka'，而非 localhost
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092

      # KRaft 控制器配置
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka:9093

      # 数据目录与集群 ID
      KAFKA_LOG_DIRS: /var/lib/kafka/data
      CLUSTER_ID: "MkU3OEVBNTwNTIJENDM2Qk"

      # 单机环境核心防坑参数
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1

      # 开启自动创建 Topic (方便测试)
      KAFKA_AUTO_CREATE_TOPICS_ENABLE: "true"
    volumes:
      - ./kafka/data:/var/lib/kafka/data
      - ./kafka/logs:/opt/kafka/logs
```

### 2.2 关键参数说明

- **KAFKA_ADVERTISED_LISTENERS**：决定 Kafka 告知客户端的连接地址。在 Docker 环境中，若需其他容器（如 Kafka-UI）访问，**必须**设置为容器服务名（如 `kafka:9092`）；若仅本机命令行测试，可设为 `localhost:9092`。
- **KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR**：单机部署必须设为 1，否则 Kafka 会因无法创建内部系统 Topic 而陷入死循环。
- **CLUSTER_ID**：KRaft 模式启动必需的集群唯一标识，可使用固定 Base64 字符串或运行 `kafka-storage.sh random-uuid` 生成。

## 3. Kafka-UI 部署配置

### 3.1 添加 Kafka-UI 服务

在 `docker-compose.yml` 中追加 `kafka-ui` 服务，使其与 Kafka 处于同一网络：

```yaml
  kafka-ui:
    image: provectuslabs/kafka-ui:v0.7.2
    container_name: kafka-ui
    restart: always
    ports:
      - "8080:8080"
    environment:
      DYNAMIC_CONFIG_ENABLED: 'true'
      KAFKA_CLUSTERS_0_NAME: local-kafka-3.9
      # 通过 Docker 内部网络使用服务名连接 Kafka
      KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS: kafka:9092
    depends_on:
      - kafka
```

### 3.2 启动与访问

```bash
# 启动所有服务
docker-compose up -d

# 查看 Kafka-UI 日志确认连接状态
docker logs -f kafka-ui
```

启动成功后，浏览器访问 `http://localhost:8080` 即可进入可视化管理界面。

## 4. 常见故障排查

### 4.1 权限报错：AccessDeniedException

- **现象：** 容器启动日志出现 `java.nio.file.AccessDeniedException: /var/lib/kafka/data/bootstrap.checkpoint.tmp`。
- **原因：** 宿主机挂载目录的所有者非 `1000:1000`，导致容器内 `appuser` 无权写入。
- **解决方案：**

```bash
docker-compose down
sudo chown -R 1000:1000 ./data ./logs
docker-compose up -d
```

### 4.2 网络连接报错：localhost vs kafka

- **现象：** Kafka-UI 界面提示 500 Internal Server Error，日志显示 `Connection to node 1 (localhost/127.0.0.1:9092) could not be established`。

- **原因：** Kafka 的 `KAFKA_ADVERTISED_LISTENERS` 配置为 `localhost`，导致 Kafka-UI 容器尝试连接自身而非 Kafka 容器。

- **解决方案：**

  1. 修改 `docker-compose.yml` 中 Kafka 的环境变量：

     ```yaml
     KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
     ```

  2. 必须清理旧数据（Kafka 会缓存旧的元数据地址）：

     ```bash
     docker-compose down
     sudo rm -rf ./data/* ./logs/*
     sudo chown -R 1000:1000 ./data ./logs
     docker-compose up -d
     ```

> **注意：** 修改 `KAFKA_ADVERTISED_LISTENERS` 后，仅重启容器无效，必须删除旧数据目录让 Kafka 重新格式化元数据。
